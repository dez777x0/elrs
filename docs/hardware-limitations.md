# Ограничения и честные ожидания

## Web Serial

- Требуется **HTTPS** или `localhost`, и разрешение пользователя на доступ к порту.
- Некоторые USB‑UART адаптеры не поддерживаются драйвером ОС в режиме, видимом браузеру.
- **iOS Safari** не предоставляет Web Serial для произвольных USB‑UART — проводная прошивка через «голый» браузер недоступна.

## Passthrough (Betaflight / INAV)

- FC должен отвечать в CLI по выбранному UART; baud по умолчанию 115200 (настраивается).
- Автодетект порта RX опирается на `resource` / `serial` в выводе CLI; при нестандартной схеме проводов нужен **Expert Mode** с ручным индексом UART.
- Half‑duplex (GHST) и full‑duplex (CRSF) используют разные параметры `serialpassthrough`; логика повторяет проверенные паттерны, но экзотические конфигурации могут потребовать ручных шагов.

## ESP (esptool-js)

- Прошивка идёт через ROM‑загрузчик Espressif; для **passthrough** возможны обрывы — уменьшайте размер блока записи в Expert Mode.
- **WebUSB** в MVP ориентирован на устройства с CDC bulk по известным дескрипторам; при отсутствии совместимого интерфейса используйте UART + Web Serial.

## OTA

- Устройство должно быть в режиме Wi‑Fi (точка доступа или известный хост). Хост по умолчанию `http://10.0.0.1` задаётся пользователем.
- Конкретный URL загрузки зависит от прошивки ExpressLRS на устройстве; при смене API потребуется обновление `OtaHttpTransport`.

## WebUSB

- В этом приложении **прошивка ESP через esptool-js привязана к Web Serial API** (`SerialPort`). **WebUSB** не заменяет этот путь для типичного UART-адаптера.
- Кнопка «Проверить WebUSB» в Expert Mode только проверяет доступность API и открытие устройства; это не сценарий прошивки.

## Native bridge (оболочка)

- На iOS и в обёртках UART может быть доступен через **`window.__ELRS_FLASHER_NATIVE__`**. Для полного цикла прошивки оболочка должна либо реализовать **`getSerialPortForEsptool`**, либо подменить **`navigator.serial`**. Подробно: [native-bridge.md](./native-bridge.md).
