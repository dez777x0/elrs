# ELRS Web Flasher: установка и использование

Руководство для конечного пользователя приложения **`web-flasher/`** (версия см. в шапке интерфейса или в `web-flasher/package.json`).

---

## 1. Что понадобится

| Что | Зачем |
|-----|--------|
| **Браузер Chromium** | Chrome, Edge или другой на движке Chromium с поддержкой **Web Serial** (основной способ прошивки по USB‑UART). |
| **HTTPS или localhost** | Web Serial работает только в [безопасном контексте](https://developer.mozilla.org/docs/Web/Security/Secure_Contexts): сайт по `https://`, либо `http://localhost`, либо `http://127.0.0.1`. |
| **USB‑кабель и UART** | Для проводной прошивки ESP — кабель к плате/адаптеру, драйвер USB‑UART установлен в системе. |
| **Файл прошивки** | `.bin` и/или `.zip` с manifest ExpressLRS (собранный заранее, **без** облачной сборки в этом приложении). |

**iPhone / iPad (Safari):** проводной UART через обычный браузер **недоступен**. Используйте режим **OTA / Wi‑Fi** или нативное приложение с [Native bridge](./native-bridge.md).

Подробнее по платформам: [transport-matrix.md](./transport-matrix.md), [hardware-limitations.md](./hardware-limitations.md).

## 2. Как «установить» и открыть приложение

### Вариант A — Уже размещённый сайт

Если команда или сообщество выложили собранный flasher на **HTTPS**, откройте ссылку в Chromium. Дальше действуйте по разделу [«Как пользоваться»](#4-как-пользоваться-пошагово).

### Вариант B — Запуск на своём компьютере (разработка / локально)

Нужны **Node.js** (рекомендуется LTS) и **git** (если клонируете репозиторий).

```bash
cd web-flasher
npm install
npm run dev
```

В терминале появится адрес (обычно `http://localhost:5173`). Откройте его в Chrome или Edge — для **localhost** Web Serial разрешён.

Проверка production-сборки без деплоя:

```bash
npm run build
npm run preview -- --host 127.0.0.1 --port 4173
```

Откройте `http://127.0.0.1:4173`.

### Вариант C — Свой сервер (статический хостинг)

Соберите проект и выложите содержимое **`dist/`** на хостинг с **HTTPS**. Подробно: [web-flasher-deployment.md](./web-flasher-deployment.md).

### PWA («Установить приложение»)

В поддерживаемом браузере можно добавить сайт на главный экран / в меню «Приложения» — удобно на планшете для **OTA**. Прошивка по UART всё равно требует подходящего браузера и контекста (HTTPS / localhost).

## 3. Выбор файла прошивки

1. Нажмите зону **«Выбрать файл прошивки»** или перетащите файлы в прямоугольник.
2. Поддерживаются:
   - один файл **`.bin`** или **`.bin.gz`** (gzip-сжатый бинарник; распаковка в браузере, нужен актуальный Chromium);
   - архив **`.zip`** с `firmware-manifest.json` (или запасной `manifest.json`);
   - **несколько файлов сразу**: например **`прошивка.bin` + `метаданные.json`** или **`прошивка.bin.gz` + `прошивка.bin.json`** (удобный sidecar — удерживайте Ctrl/⌘ при выборе).
3. После выбора откроется **сводка**: сегменты, чип, таргет, контрольные суммы. Проверьте, что всё совпадает с вашим железом.

Формат ZIP и sidecar: [firmware-manifest-format.md](./firmware-manifest-format.md).

## 4. Как пользоваться (пошагово)

### 4.1. Общий порядок для UART (прямой / passthrough)

1. Выберите файл прошивки (см. выше).
2. Укажите **режим**:
   - **Прямой UART** — ESP подключён к USB‑UART напрямую (или уже в режиме загрузчика).
   - **Betaflight / INAV / EdgeTX passthrough** — прошивка через полётник и `serialpassthrough` (см. ниже).
3. Нажмите **«Подключить устройство (UART)»**. Браузер покажет список последовательных портов — выберите нужный.
4. Нажмите **«Прошить»**. Следите за **фазами** (connect → detect → … → flash → verify → reboot) и **логом** внизу.
5. При ошибке текст появится в блоке **«Ошибка»**; лог можно **скопировать** или **скачать** для отчёта.

### 4.2. Прямой UART

- Подключите RX/ESP к USB‑UART (GND общий, TX/RX перекрёстно, при необходимости линии EN/IO0 по схеме платы).
- Режим: **Прямой UART**.
- При сбоях входа в загрузчик откройте **Expert Mode** и попробуйте другой **esptool reset** (`no_reset` / `default_reset`), при обрывах уменьшите **Flash block size**.

### 4.3. Betaflight / INAV passthrough

- Полётник подключён по USB, в CLI доступен тот же UART, к которому подключён ELRS RX.
- Режим: **Betaflight passthrough** или **INAV passthrough**.
- Для **GHST** включите в Expert **Half duplex (GHST)**; для CRSF обычно выключено.
- При необходимости задайте **UART индекс** вручную (Expert), если автоопределение не сработало.
- Нажмите **Подключить устройство** → **Прошить**. Приложение само войдёт в CLI, выполнит `serialpassthrough` и прошьёт ESP.

### 4.4. EdgeTX passthrough

- Подключите радио / модуль так, чтобы был доступен CLI EdgeTX по выбранному порту.
- Режим: **EdgeTX passthrough**.
- В Expert при необходимости отметьте **EdgeTX backpack (RF module)** для сценария с RF‑модулем.

### 4.5. OTA / Wi‑Fi

- RX в режиме точки доступа или в вашей сети; известен **URL** веб‑обновления (часто `http://10.0.0.1`).
- Режим: **OTA / Wi‑Fi**.
- Укажите **хост** и **путь загрузки** (кнопки‑пресеты: `update`, `upload`, `api/update` — зависит от прошивки RX).
- Кнопка **«Подключить устройство»** для OTA не нужна — сразу **«Прошить»** (загрузка файла на устройство).

Подсказки по URL: [ota-endpoints.md](./ota-endpoints.md).

## 5. Expert Mode (кратко)

Открывается кнопкой **Expert Mode**. Типичные опции:

| Опция | Назначение |
|--------|------------|
| **UART backend** | Web Serial в браузере или **Native bridge**, если приложение встроено в оболочку (iOS и т.д.). |
| **Force Flash** | Игнорировать несовпадение таргета/чипа — только осознанно, с галочкой подтверждения. |
| **Half duplex (GHST)** | Режим для GHST вместо CRSF. |
| **UART индекс / Passthrough baud** | Ручные значения для passthrough. |
| **esptool reset** | Стратегия сброса чипа при подключении esptool-js. |
| **Flash block size** | Уменьшить при нестабильной связи. |
| **Полное стирание flash (erase all)** | Опасно: очистит весь flash перед записью. |
| **Sidecar JSON** | Метаданные к `.bin`, если нет manifest в ZIP (или не использовали мультивыбор). |

## 6. Если что-то пошло не так

1. Прочитайте **сообщение об ошибке** и **лог** (часто там есть подсказка).
2. Проверьте кабель, питание, правильный **COM‑порт**, драйвер USB‑UART.
3. Для passthrough: версия BF/INAV, `serialrx_provider`, не занят ли порт другой программой.
4. Для OTA: откройте тот же **хост** в браузере вручную; смените **путь** (пресеты).
5. Документы: [honest-gap.md](./honest-gap.md) (что сознательно не доведено до «идеала»), [hardware-limitations.md](./hardware-limitations.md).

Ручной регресс на железе: [manual-test-checklist.md](./manual-test-checklist.md).
